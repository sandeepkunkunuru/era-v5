Session 3 · Assignment

A 40B India-first model

Design a 40B model — Gemma-3-class, strong at coding, agentic work, and Indic languages, reasoning from an Indian vantage. India-first = three things, not translation: corpus composition + a values constitution + tokenizer efficiency. Every line below is a choice and its reason. The vocab number is measured, not asserted.

§1Fertility → vocab size measured

Trained candidate BPE tokenizers (NFKC + Metaspace, Indic-atomic) at 32k–256k on an Indic-heavy mix, measured fertility (tokens/word) on FLORES-200 devtest — parallel text, so differences are script/tokenizer, not content. Validates against Sarvam-1 (our 64k: indic-mean 2.06 / en 1.41, inside their 1.4–2.1).

Target Indic premium ≤ 1.5× English — reachable for Indo-Aryan/Perso-Arabic (hi, ur, pa, bn), not for Dravidian (ml/kn/te/ta stay 1.8–2.2× at every vocab). The binding constraint is morphology, not script: agglutinative words are long, so subword vocab alone can't equalize them — that needs morpheme-aware pre-tokenization or a per-script budget boost (stated, not hidden). The number: measured knee (~200k) and Tao-optimal for 40B (~200k) agree; breadth (13 langs, 10 scripts) + negligible embedding cost (256k×~6k hidden ≈ 1.6B, ~4% of 40B) → round up to 256k.

§2Data

Pre-training

Mix set by DoReMi/DSIR (learned domain weights), not hand-tuned. Within Indic, temperature- smooth (α≈0.3) by verified tokens so Hindi doesn't crowd the tail — but cap synthetic: Sangraha is 251B total yet verified Assamese ≈ 0.3B, so a synthetic-heavy tail teaches translationese. Web = FineWeb-Edu quality filter (retrain classifier for Indic); code = The Stack v2 (license + near-dedup); math = DeepSeekMath recall + OpenMathInstruct-2.

Post-training / RL

SFT (Tülu-3 mix + Indic instructions, Airavata-style) → DPO (reward-model-free preference) → RLVR (unit-tests for code, answer-check for math). Agentic data = ReAct traces + tool-use trajectories (ToolLLM/Gorilla). Constitutional AI with an explicit Indian-values constitution (pluralism, Indian legal/social norms, code-mixing) → RLAIF — this is the worldview lever, not translation.

§3Cleaning

Eight stages, in order: extract (boilerplate/HTML strip) → lang-ID (fastText/CLD3) → CCNet normalize → Gopher quality heuristics → MinHash + exact-substring dedup (~10× less memorization) → n-gram decontam → PII + toxicity → manifest (per-shard provenance + hash → reproducible: same input+script → same output). Indic-specific: Unicode NFC + script/transliteration normalization (indic-nlp-library), Brahmic ZWJ/ZWNJ preserved (the V4 46-garbage-token bug); an Indic-trained quality classifier (the FineWeb edu-classifier is English-only). Code: license filter + near-dedup + optional execution filter. Run for real in Session 4 →

§5Why this is India-first

Three levers together: composition (Indic over-weighted ~25× its web share), worldview (an Indian-values constitution shapes RLAIF), and efficiency (an Indic-atomic tokenizer so Indian users don't pay the 3–5× token tax; Petrov 2023). The vocab number is the hinge — it converts "supports Indic" into "cheap in Indic."
