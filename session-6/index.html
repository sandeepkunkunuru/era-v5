01The path, end to end — one command

A small but complete data-execution system. python run_demo.py runs all of it without manual intervention and writes a machine-readable evidence bundle that the code generates — nothing hardcoded.

documentstokenized shardsmanifestsmixture schedule packingbatchestrainingconsumption ledger learning ledgercheckpointcrash resumereplayforkaudit

The one idea everything rests on. Every batch B(t) is a pure, reconstructable function of (master_seed, compiled_schedule, shard_set, sampler_state@t).

The sampler state is tiny and serialisable, so a checkpoint captures the exact stream position. That is what makes resume, replay and fork provable instead of asserted — restore the state, recompute the batch, compare its content hash. The batch payload is integer-only (token ids + masks), so hashes are identical across machines; the only float math lives in a throwaway model that no proof depends on.

02Crash, resume, replay, fork — the proofs

The run deliberately crashes mid-flight, resumes from the last checkpoint, replays a historical interval, and forks a branch. Each claim is checked against a hash, not a log message.

Why replay needs no model. The data stream never depends on the weights, the wall clock, or a global RNG — so a past interval is rebuilt from the recorded state alone. This is the lecture's rule made literal: on replay you read and send the recorded order, you don't recalculate it.

03Packing, masks and the loss rule

Two packing policies, chosen by data type: concat for pretraining lanes (high utilization), structure-preserving for SFT/agentic traces (one trajectory per sequence, never leaking unrelated examples together). Every packed sequence carries a loss mask, segment ids (block-diagonal attention — no attention across a boundary) and per-document position ids.

A real agentic sequence from the run — agentic-007, step 30

22 loss-bearing 18 masked context 88 pad

The user request and the tool observation are context — read, never trained on. Applying loss there would teach the model to invent tool results instead of calling the tool. Only the assistant's plan and final answer bear loss.

An honest trade, visible in the numbers. Structure-preserving packing leaves that sequence 69% padded — it refuses to fill the gap with an unrelated document. Concat packing on pretraining lanes runs far denser, and the run averages 85.6% utilization overall with 80.9% of capacity loss-bearing.

Correctness first, density second — and the cost is reported rather than hidden.

04OPUS decisions — and the finding

Every candidate is scored on its token prefix and recorded as accept / reject / defer, with a protected-floor override when a scarce lane would otherwise be starved. 2,287 decisions were logged across the run.

Indic and agentic were accepted on merit exactly zero times. Every single one that entered a batch did so through the protected-floor override — 239 and 60 of them.

This is Session 5's warning reproduced by a running system rather than argued: a selector whose proxy is English- and code-benchmark-driven does not merely under-weight the scarce lanes, it takes all of them to zero. The floor is not a safety margin — without it, the two capabilities this project exists for would never be trained at all. Mixture compliance held anyway: planned and actual lane shares match, and every stage floor was met at every step.

05Shards, manifests and the evaluation firewall

Shards are immutable binary token arrays. Each manifest carries the frozen tokenizer hash, a content hash, provenance, the cleaning-pipeline code hash, and dedup / contamination / eval-overlap status — the gate that decides whether a shard may be trained on at all. Both hashes are re-verified on load; a test flips one token and confirms the check fails.

CheckCountResult

The firewall is enforced twice — eval shards are never marked trainable, and an independent audit scans every consumed batch for a leaked eval document.
