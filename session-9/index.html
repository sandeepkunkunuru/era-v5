Session 9 · Loss functions & output heads

Where the prediction
becomes a number

A hidden state of 4,096 numbers is not a token and it is not a probability. Something has to turn it into a prediction, and then something has to turn the gap between that prediction and the truth into one scalar an optimiser can push down. This is that machinery — and the bill it sends, which arrives at the very last layer after all the clever attention work is done.

32×the logits tensor against the hidden state that produced it — V/D, and it does not care about batch or context

536.9Mthe output head at V5's shape — and Session 7 removed the input table there was to tie it to

The gradient is softmax(z) − onehot(y): the true token pushed up by 1−p, every other pushed down by exactly its own probability. It always sums to zero — so the loss can move logit mass around but never move the whole vector up or down together. That unwatched direction is why log Z drifts, and why soft-capping exists.

02 The third bill

Session 8 spent itself on two bills: attention's compute, which grows as T², and the KV cache, which grows as T. There is a third, it grows as T×V, and it is larger than the one everybody budgets for.

Weight tying is the standard escape from the parameter half of this, and Session 7 closed it. With a byte-codec input side there is no [V,D] input table to tie to — so the head stays a dense 536.9M matrix unless something is invented, which is what makes a factored head an open V5 question rather than a solved one.

03 Four quiet bugs

All four live in the few lines between the model's output and the scalar. None of them raises an exception, and every one of them makes the loss look better. Numbers below are measured, on a trained model — on an untrained one every position costs ln(V) and none of this is visible.

04 The same loss, for a fraction of the memory

Chunking computes the logits a slice at a time and recomputes them in the backward. The arithmetic goes up, the memory goes down, and the number does not move at all — measured here to the ninth decimal.

05 A second head, and something in the curve

Add a head predicting t+2 and the losses simply add. Both start at ln(V) — they must, since at step 0 "the token after next" is exactly as unknown as "the next token". Then the gap opens, and widens, which is the extra supervision MTP is bought with.

Two hypotheses, two refutations. What survives is the observation: reproducible under a fixed seed, identical in both arms, crossing at the same step. The next discriminating test is a frozen random trunk — if the effect is about how much context the trunk carries, freezing it should stop head 1 from ever overtaking. Not run, and not claimed either way.

It is worth reporting rather than deleting, because the brief presents "head k's loss sits above head 1's" as what an MTP curve shows, and for the first fifty steps of a real run it is simply not true. Anyone reading an early MTP curve as evidence the extra head is working is reading a regime nobody has characterised.
